## Stage 5 - Deduplication and lifecycle

1. Implement company/title/location normalization and tracking-safe URL canonicalization.
2. Implement exact source identity, guarded application-URL match, multi-signal similarity, versioned thresholds, and decision persistence.
3. Implement provenance-preserving merge and potential-duplicate flagging.
4. Implement discovered-to-active flow, omission counters on successful full checks, explicit unavailable handling, grace-based expiry, and lifecycle events.

Required edge tests:

- same title at two companies remains separate;
- same company/title but different locations or requisition IDs remains separate when evidence conflicts;
- same vacancy from two ATS sources merges only with strong corroborating signals;
- generic company apply URL never causes a mass merge;
- medium confidence leaves two `potential_duplicate` jobs;
- repeated source observation updates last-seen rather than creating a row;
- one timeout does not expire anything;
- source-wide failure does not increment omission counts;
- all appearances explicitly closed can expire the canonical listing.

Gate: every merge decision is explainable and reversible from retained appearances.

## Risks and mitigations

- **Resume layout drift:** keep extraction and parsing separate, version parsers, retain unmapped text, and report ambiguity.
- **Fabricated certainty:** every field carries source/origin status; no LLM is needed for this phase.
- **Candidate data loss:** immutable snapshots, content-addressed sources, trust precedence, transactions, and backup tests.
- **Duplicate false positives:** require multiple signals, store decisions, preserve appearances, and prefer review over merge.
- **Provider schema/terms changes:** primary-source capability notes, raw snapshots, schema-drift tests, per-connector isolation, and revalidation before deployment.
- **SQLite contention:** short serialized writes, WAL/busy timeout, and database leases; move to PostgreSQL only when observed workload justifies it.
- **PII leakage:** restrictive source storage, redacted structured logs, private examples, and no public API by default.
- **Overbuilding:** no ranking, embeddings, application model, browser scraper, generic crawler, broker, or microservice in these milestones.
